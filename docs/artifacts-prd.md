# 作品集（Artifacts）功能需求说明

## 一、背景与目标

当前主流 Agent 产品以对话交互为核心，但在数据智能场景中，用户更关注可沉淀、可复用、可自动更新的分析成果，例如固定周期的经营报表、业务分析报告和可视化看板。

当用户通过 Agent 生成高价值结果后，往往希望：
- 不再重复对话生成
- 能长期保存并随时间自动更新
- 可直接访问和共享
- 具备类似 BI 报表的稳定体验

因此，需要构建「作品集（Artifacts）」功能，用于将 Agent 生成的成果固化为可自动执行的数据应用。

---

## 二、典型场景示例

### 用户使用 Agent 创建分析报告的过程

**场景：** 用户要求分析"项目26"的经营数据

**Agent 执行流程：**

| 步骤 | 调用的 MCP 工具 | 作用 |
|------|-----------------|------|
| 1 | `get_table_comment` | 查询表结构，了解数据模型 |
| 2 | `get_create_sql` | 获取建表语句，确认字段 |
| 3 | `query_data` (多次) | 执行 SQL 查询获取数据 |

**数据获取内容：**
- 建筑面积、租赁面积、租户数量
- 空置率趋势（Q1-Q4）
- 租金水平趋势
- 各行业租赁分布
- 同区域项目对比

**最终输出 - Artifact 内容：**

| 章节 | 内容形式 |
|------|----------|
| 📊 核心数据概览 | 数据表格 |
| 📈 市场绩效趋势 | ECharts 图表 |
| 🏢 行业结构分析 | 行业分布表格 |
| 📊 市场竞争对比 | 对比表格 |
| 🎯 关键洞察与建议 | 文字分析 |

**Artifact 展示形式：**
- 右侧独立面板展示 HTML 报告
- 工具栏：Code/Preview 切换、Refresh、Download Artifact、Close

## 三、核心设计原则

### 作品 = 展示页面 + 专属取数 Skill

```
Agent 对话
    ↓
生成 HTML（展示） + 取数逻辑（SQL/API调用）
    ↓
发布为作品
    ↓
系统自动固化一个专属 Skill（取数服务）
    ↓
HTML 通过 Skill API 获取数据
    ↓
定时刷新 = 定时调用 Skill API
```

### 平台职责（极简）

| 负责 | 不负责 |
|------|--------|
| 存储 HTML + Skill + 元数据 | 解析 SQL |
| 管理权限 | 管理参数 |
| 定时调用 Skill | 理解业务逻辑 |

## 四、信息架构

### 4.1 一级菜单：作品集

新增一级菜单「作品集」，定位类似"智能体市场"，存储用户发布的分析成果（Artifacts）。

### 4.2 展示形式

采用卡片式布局，每个卡片对应一个已发布作品：

| 展示内容 | 说明 |
|----------|------|
| 作品名称 | 必填 |
| 简要描述 | 必填 |
| 作者 | 系统自动获取 |
| 最近刷新时间 | 系统记录 |
| 刷新周期标识 | 手动/每小时/每天/每周/每月 |
| 权限状态 | MVP 仅支持私有 |

### 4.3 卡片交互

- 点击卡片进入作品详情页
- 详情页使用 iframe 展示 HTML 内容

---

## 五、Artifact 发布机制

### 5.1 发布入口

**位置：** Agent 对话的 Artifact 消息块工具栏

**触发条件：** 当 Agent 生成 HTML/ECharts 类型的 Artifact 时，显示「发布为作品」按钮

### 5.2 支持发布的内容类型

当前仅支持结构化可渲染成果：
- HTML 报告
- ECharts 图表或仪表板

不支持：
- 纯文本对话
- 非结构化内容
- 外部文件下载结果

### 5.3 发布配置项

**1）基础信息（必填）**
- 作品名称
- 作品描述

**2）刷新策略（必填）**
- 手动刷新
- 每小时
- 每天
- 每周
- 每月

## 六、技术实现方案

### 6.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                        前端                              │
├─────────────────────────────────────────────────────────┤
│  路由: /artifacts → ArtifactsGallery 组件               │
│  菜单: 新增一级菜单「作品集」                            │
│  发布: 在现有 Artifact 组件中添加发布按钮                │
└─────────────────────────────────────────────────────────┘
                           ↓ API
┌─────────────────────────────────────────────────────────┐
│                        后端                              │
├─────────────────────────────────────────────────────────┤
│  路由: /api/artifacts                                   │
│  模型: Artifact.js (MongoDB)                            │
│  定时: node-cron 执行刷新任务                           │
└─────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────┐
│                      存储层                              │
├─────────────────────────────────────────────────────────┤
│  MongoDB: 作品元数据                                    │
│  文件存储: HTML 文件（本地或对象存储）                   │
└─────────────────────────────────────────────────────────┘
```

### 6.2 前端改造

#### 6.2.1 新增路由

**文件：** `client/src/routes/index.tsx`

**内容：** 新增 `/artifacts` 路由

**参考：** 现有 `/agents` 路由实现

#### 6.2.2 新增菜单入口

**位置：** 侧边栏导航

**内容：** 在"智能体市场"旁边新增"作品集"菜单项

**参考：** `AgentMarketplaceButton` 组件

#### 6.2.3 新增组件

| 组件名 | 功能 | 文件位置 |
|--------|------|----------|
| ArtifactsGallery | 作品集主页面，卡片列表 | `client/src/components/ArtifactsGallery/` |
| ArtifactCard | 单个作品卡片 | `client/src/components/ArtifactsGallery/` |
| ArtifactDetail | 作品详情页（iframe 展示） | `client/src/components/ArtifactsGallery/` |
| PublishArtifactModal | 发布弹窗 | `client/src/components/ArtifactsGallery/` |

#### 6.2.4 修改现有组件

**文件：** `client/src/components/Artifacts/` 目录

**内容：** 在 Artifact 工具栏添加「发布为作品」按钮

### 6.3 后端改造

#### 6.3.1 新增 API 路由

**文件：** `api/server/routes/artifacts.js`

| 接口 | 方法 | 功能 |
|------|------|------|
| `/api/artifacts` | GET | 获取作品列表 |
| `/api/artifacts` | POST | 发布新作品 |
| `/api/artifacts/:id` | GET | 获取作品详情 |
| `/api/artifacts/:id` | DELETE | 删除作品 |
| `/api/artifacts/:id/refresh` | POST | 手动刷新作品 |

#### 6.3.2 新增数据模型

**文件：** `api/models/Artifact.js`

**字段定义：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 唯一标识 |
| name | String | 作品名称 |
| description | String | 描述 |
| authorId | ObjectId | 作者 ID |
| htmlContent | String | HTML 内容或存储路径 |
| skillId | String | 关联的 Skill ID（MVP 可为空） |
| refreshPolicy | String | 刷新策略：manual/hourly/daily/weekly/monthly |
| lastRefreshTime | Date | 最后刷新时间 |
| createdAt | Date | 创建时间 |
| updatedAt | Date | 更新时间 |

#### 6.3.3 定时刷新机制

**方案：** 使用 node-cron 库

**实现：**
1. 后端启动时初始化定时任务调度器
2. 根据作品的 refreshPolicy 设置 cron 表达式
3. 到达时间后调用作品的 skillId 获取数据

**MVP 简化：** 先实现手动刷新，定时刷新作为后续优化

### 6.4 存储方案

#### 6.4.1 元数据存储

**方案：** MongoDB

**集合：** `artifacts`

#### 6.4.2 HTML 文件存储

**MVP 方案：** 本地文件系统

- 存储路径：`/uploads/artifacts/{artifactId}.html`
- 通过静态文件服务访问

**后续优化：** 对象存储（OSS/S3）

## 九、风险与依赖

1. **现有 Artifact 组件复杂度**：需要深入理解现有代码结构
2. **Skill 自动生成**：MVP 阶段可简化，先不做
3. **HTML 存储安全**：需要考虑 XSS 防护
4. **定时任务可靠性**：需要考虑服务重启后任务恢复
